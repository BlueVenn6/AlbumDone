## 有证据的根因与改动

1. Android 原导入会要求 CameraRoll 补齐每张图片尺寸，可能逐张打开原图。新路径使用 MediaStore 分页读取元数据，继续使用 `content://media`，仅在查重、AI 筛选和回看需要时补读缺失尺寸。取消后不发布末页，不缓存不完整结果；异常游标直接报错。
2. 删除完成原先没有核对媒体库中的实际结果，也没有精确清理照片所属缓存。现在先核对原图不存在，再清理对应预览及两类哈希缓存；删除计数只包含核对通过的照片，并记录原图字节、缓存字节和可用空间差值。CameraRoll 原生模块只有一个待确认 Promise，因此跨页面删除任务串行执行。
3. Windows 回收站保留原图，所以不能把移入回收站等同于释放原图空间。保留回收站操作，另提供有原生确认框的永久删除。两个删除入口统一核对原文件消失，并清理所属缩略图和索引；缓存清理失败单独报告。
4. Android 大重复组改为 FlatList；Windows 大重复组只挂载可见行。保留所有照片的访问、保留/删除选择功能。
5. Android 相册重新读取系统计数，避免旧快照覆盖新计数。回看等待所有图片载入后才能导出，并释放截图临时文件，防止空白图和重复导出。
6. Windows 连接探测采用共享层的预期答复判定，HTTP 200 中的错误文字不能成为成功。截至后续复核，37 个固定模型的协议、请求和解析有回归覆盖，这不等于 37 个模型已实网调用；后续根因与实际页面结果见 CORE_BEHAVIOR_REVIEW_2026-10-12.zh-CN.md。
7. Windows 开发启动等待配置端口，Vite 不再自行跳到另一端口。LAN 两个候选端口均占用时及时失败，失败后可恢复，并发启动合并；HTTP 错误转发到 WebSocket 的崩溃有同路径回归测试。Android 修正 `fc` / `fd` 开头正常云域名被误判为内网的问题。

## 模型与依赖证据

DeepSeek 官方 [更新记录](https://api-docs.deepseek.com/updates) 与 [模型定价表](https://api-docs.deepseek.com/quick_start/pricing) 是本轮 Flash 迁移依据：旧 `deepseek-v4-flash` 与实验视觉名称迁移为 `deepseek-flash`，使用视觉请求；Pro 仍按文本模型处理。旧配置加载和默认路由同样迁移。Kimi 保留 `kimi-k2.5` 和 temperature=1。

部分厂商官方文档在本机返回访问拒绝或超时；未获得证据的型号不能宣称均未过期。没有在日志或聊天中读取、展示用户密钥，也没有对私人照片发起外部 AI 请求。实际账号权限与识图正确性仍需应用内连接/已知内容测试图验收。

依赖告警分别审查打包运行时与构建工具。Windows `sharp`、`proxy-addr` 有官方可用修补版本；必须核对实际安装版本与 lockfile，不能只相信 npm 的成功退出码。Android 构建工具依赖中的 braces / sprintf-js 在本轮查询的 registry 中没有可用修补版；不通过升级整套 React Native 来掩盖该事实。此类工具依赖是否进入 APK 需检查实际 Metro source map；告警不因记录为工具依赖就自动消失。

## 验收路径与验证等级

电脑端检查包含 TypeScript、共享行为测试、移动端回归、Android 原生编译、Windows 真实文件删除/端口测试、production renderer，以及最终产物来源核对。具体命令结果保存在本轮验收记录，失败不得转为通过。

Android 本地包名称为 **AlbumDone 验收版**，独立 application ID，build 17。它使用本机测试签名并内置 JS，离线启动不依赖电脑 Metro。用户必须确认启动的是这个验收版，不能用旧正式图标验收。

用户手机复验使用专用可丢弃图库：导入 1000–2000 张，记录首批可见与总耗时，滚动/切图/取消/重新进入；删除 200 张前后比较系统存储可用空间和应用存储日志，核对原图及计数；检查取消、部分失败与重启；检查 AI 已知图片内容；回看生成、图片载入和导出。不要用唯一原图测试永久删除。

“存储空间”与 RAM 不同。原图从系统媒体库永久删除后应释放其所属卷上的存储；系统界面的统计可能延迟，其他应用写入也会影响净差值。主存储卷的可用空间差值不能证明 SD 卡卷变化，云端占位图也不能按云端原图大小计算本地释放量。不得承诺删除任意 200 张照片后 RAM 或整机净可用空间必然按固定数值变化。

State B 表示源码测试通过；State C 表示确切包已生成并核对但尚未真机验收；只有安装确切包并重新执行原始问题路径才可进入 State D。用户已说明当前不能提供连接设备和正式签名，但能自行安装本地 APK，因此不能以缺少 ADB 为由提前结束修复工作。

Android 正式上传签名、商店隐私/支持页的真实联系方式与公开 URL、用户真实手机表现、实际 AI 账号调用仍是上架前的放行项。本地验收 APK 不应冒充可售卖正式发布包。
